# ESL-Bench: An Event-Driven Synthetic Longitudinal Benchmark for Health Agents

## 研究问题

纵向健康Agent需要在多数据源轨迹（设备流数据、临床检查、生活事件）中进行推理，但评估它们极其困难：真实健康数据无法大规模发布，且时间相关的归因问题在缺乏结构化Ground Truth的情况下几乎没有确定性答案。如何构建一个**可大规模生成、有确定性答案、覆盖多维度评估**的纵向健康Agent benchmark？

## 困难点

1. **隐私约束**：真实健康数据受严格隐私法规保护，无法大规模发布。
2. **时间动态建模**：健康指标受多种事件影响，呈现复杂的时间动态。
3. **Ground Truth缺失**：真实场景中很难获得关于健康变化因果关系的确定性答案。
4. **评估维度多样**：健康Agent需要具备查找、趋势分析、比较、异常检测、解释等多种能力。

## 解决方法

### ESL-Bench 事件驱动合成框架

ESL-Bench设计了一个精巧的**混合合成管线**：将语义内容生成交给LLM，将数值动态计算交给算法模拟。

#### 1. 合成用户生成

为每个合成用户生成：
- **健康档案**：基本信息、病史、生活方式
- **多阶段叙事计划**：1-5年的生活事件序列
- **日常设备数据**：连续的设备测量值（如心率、步数、睡眠）
- **定期检查记录**：间歇性的临床检查结果
- **事件日志**：带有明确因果参数的事件记录

#### 2. 事件驱动的指标动态模型（核心技术创新）

每个健康指标遵循一个**基线随机过程**，被离散事件通过数学模型驱动：

- **Sigmoid起始（Sigmoid-onset）**：事件影响的渐进出现
- **指数衰减（Exponential-decay）**：事件影响的逐渐消退
- **饱和约束（Saturation constraints）**：指标不超过生理极限
- **投影约束（Projection constraints）**：确保长期趋势合理

关键特性：每个事件对每个指标的影响都有**明确的数学参数**，使得所有评估问题的答案都可以**程序化计算**。

#### 3. 混合合成管线

| 组件 | 方法 | 原因 |
|------|------|------|
| 叙事计划、事件描述 | LLM生成 | 需要语义丰富性和自然语言 |
| 指标动态、数值数据 | 算法模拟 | 需要数学精确性和一致性 |
| 评估答案 | 程序化计算 | 确保答案的确定性 |

#### 4. 评估体系

每个用户配对**100个评估查询**，覆盖5个维度×3个难度级别：

| 查询维度 | 说明 | 示例 |
|----------|------|------|
| **Lookup** | 查找特定时间点的指标值 | "3月15日的心率是多少？" |
| **Trend** | 分析指标的变化趋势 | "过去3个月BMI的变化趋势？" |
| **Comparison** | 对比不同时期或指标 | "运动前后的睡眠质量对比？" |
| **Anomaly** | 检测异常值或异常模式 | "是否有血压异常升高？" |
| **Explanation** | 解释指标变化的原因 | "为什么血糖在4月突然升高？" |

所有答案都**可从事件-指标关系中程序化计算**。

## 主要结果

- 生成**100个合成用户**，每个用户1-5年轨迹
- 评估了**13种方法**：LLMs with tools、DB-native agents、memory-augmented RAG
- **DB agents（48-58%）**显著优于**memory RAG baselines（30-38%）**
- 差距集中在**Comparison和Explanation**查询——需要多跳推理和证据归因

## 核心贡献与技术细节

### 1. "LLM + 算法"混合合成的精妙设计
ESL-Bench不是纯LLM合成，也不是纯规则合成，而是将两者的优势互补：
- LLM负责语义丰富的内容（使数据看起来自然）
- 算法负责数值精确性（使答案确定可验证）
这种混合方式避免了纯LLM合成的不一致性和纯规则合成的不自然性。

### 2. 事件-指标因果模型
通过数学模型建立事件与指标之间的明确因果关系，使得"为什么某指标发生变化"有了确定性的、可验证的答案。这是对Benchmark可验证性的一个优雅解决方案。

### 3. 隐私问题的彻底解决
100%合成数据，不涉及任何真实患者信息，彻底规避了健康数据的隐私限制。

### 4. 纵向多源数据的合成
ESL-Bench展示了如何合成**多数据源、长时间跨度的纵向数据**——这在之前的Agent benchmark中很少涉及。

## 对本课题的启示

ESL-Bench对benchmark数据合成的独特贡献：
1. **混合合成管线**（LLM语义 + 算法精确）是领域特化benchmark的优秀范式
2. **事件驱动的因果模型**确保了合成数据的可验证性
3. **隐私敏感领域**的benchmark必须通过合成方式构建
4. **程序化可计算的Ground Truth**是高质量benchmark的关键
5. 展示了如何在特定领域（健康）中应用通用的数据合成方法论
